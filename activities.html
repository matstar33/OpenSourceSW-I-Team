활동 기록

첫 기획 회의부터 공통 레이아웃 구축, 페이지별 기능 구현과 배포 준비까지 레인보우 팀이 함께 진행한 회의와 개발 과정을 날짜 순서대로 정리했습니다.

진행 일정 총 6단계 2026.10.30 ~ 11.23
참여 인원 팀원 6명 역할별 개별 브랜치 담당
구성 화면 5개 페이지 공통 헤더·푸터 레이아웃 적용
협업 방식 Issue & PR 팀원 리뷰 승인 후 병합

시간순 진행 기록

구분 필터와 정렬 버튼으로 회의 내역과 개발 단계를 확인하실 수 있습니다.

  1. 01
    2026.10.30 (금) 팀 회의 완료

    1차 킥오프 회의 및 GitHub 저장소 초기 세팅

    오픈소스 SW 활용 I조 6인 팀을 결성하고, 팀원 개개인의 역할과 프로젝트를 한곳에 소개하는 IT 개발 스튜디오형 포트폴리오 웹사이트를 주제로 선정했습니다.

    • 공식 원격 저장소(OpenSourceSW-I-Team) 생성 및 MIT 라이선스 적용
    • 협업을 위한 커밋 메시지 접두어 규칙(feat:, style:, fix:, docs:) 합의
    • 파트별 독립 작업을 위한 초기 feature 브랜치 생성 방법 공유
    참여: 팀원 전원 (6명)
    저장소 개설 MIT License 커밋 규칙 수립
  2. 02
    2026.11.03 (화) 팀 회의 완료

    2차 기획 회의 및 5개 페이지 역할 분담 확정

    전체 웹사이트의 메뉴 구성을 5개 핵심 화면으로 확정하고, 팀원 6명이 각자 맡을 영역과 브랜치 이름을 정해 GitHub Issue로 등록했습니다.

    • 메인, 팀 소개, 팀원 프로필, 프로젝트 갤러리, 활동 기록 5개 화면 구성 확정
    • README.md에 프로젝트 기획 의도, 폴더 구조, 협업 규칙 문서화 (PR #7 병합)
    • 담당자별 작업 범위와 완료 조건을 명시한 GitHub Issue #1 ~ #6 일괄 등록
    참여: 팀원 전원 (6명)
    Issue #1~#6 PR #7 병합 역할 분담 완료
  3. 03
    2026.11.03 (화) 개발 과정 완료

    기본 프로젝트 폴더 구조 및 PR 템플릿 구축

    모든 팀원이 동일한 환경에서 바로 페이지 개발을 시작할 수 있도록 초기 HTML 뼈대 파일과 공통 스타일 변수, Pull Request 양식을 구축했습니다.

    • 5개 HTML 기본 파일 및 css/, js/, images/ 표준 폴더 구성
    • 포인트 색상(#4a90e2), 기본 글자색, 폰트 등 공통 CSS 변수 정의
    • 변경 기능과 화면 캡처, 반응형 테스트 항목을 점검하는 PR 템플릿 적용
    담당: 길규철 (팀장)
    초기 디렉터리 CSS 변수 세팅 PR 템플릿
  4. 04
    2026.11.18 (수) ~ 11.19 (목) 개발 과정 완료

    공통 헤더·푸터 제작 및 모바일 반응형 메뉴 적용

    전체 페이지의 통일감을 높이기 위해 상단 고정 네비게이션 바와 하단 푸터를 구현하고, 모바일 환경에서도 편리하게 이동할 수 있도록 햄버거 메뉴를 완성했습니다.

    • 5개 전체 페이지에 동일한 로고, 상단 메뉴, 팀 GitHub 링크 푸터 마크업 반영
    • 현재 열려 있는 파일 경로를 감지해 해당 메뉴에 active 강조 스타일 자동 부여
    • 화면 너비 768px 이하에서 동작하는 모바일 햄버거 메뉴 토글 구현 (PR #8 병합)
    담당: 길규철 (feature/common-layout)
    Issue #5 완료 PR #8 병합 모바일 반응형
  5. 05
    2026.11.21 (토) ~ 11.22 (일) 개발 과정 진행 중

    파트별 상세 페이지 개발 및 1차 Pull Request 등록

    완성된 공통 레이아웃을 기반으로 각 담당자 브랜치에서 개별 페이지 콘텐츠와 반응형 UI를 제작하고, 화면 검증을 거쳐 1차 PR을 등록했습니다.

    • 활동 기록 페이지(activities.html): 시간순 타임라인, 구분 필터, 정렬 전환, 이미지 확대 모달 구현
    • 타 페이지와 병합 충돌이 발생하지 않도록 페이지 전용 스타일(css/activities.css) 및 스크립트 분리 설계
    • PC 화면과 모바일 해상도에서 텍스트 줄바꿈, 메뉴 이동, 이미지 비율 정상 표시 점검
    담당: 박정언 외 각 페이지 담당자
    Issue #4 구현 feature/activities 1차 PR 제출
  6. 06
    2026.11.23 (월) 예정 협업·배포 예정

    상호 코드 리뷰, 최종 병합 및 GitHub Pages 정식 배포

    제출된 각 브랜치의 PR을 팀원끼리 교차 리뷰한 뒤 main 브랜치로 통합하고, 전체 링크와 반응형 동작을 최종 점검하여 배포를 마무리합니다.

    • PR별 변경 파일 및 PC·모바일 화면 캡처를 확인하고 팀원 1명 이상 승인 진행
    • main 브랜치 순차 병합 및 공통 리소스 충돌 여부 점검·기록
    • GitHub Pages 배포 활성화 후 README.md에 최종 접속 주소 반영
    참여: 팀원 전원 (6명)
    코드 리뷰 최종 병합 GitHub Pages

회의 주요 합의 사항 및 협업 원칙

6명의 팀원이 일관된 코드 품질과 디자인을 유지하기 위해 세운 기준입니다.

디자인 및 화면 구현 기준

  • 레이아웃 폭 통일: 상단 헤더와 본문 컨테이너의 최대 너비를 1100px로 맞춰 페이지 이동 시 시선이 흔들리지 않도록 구성했습니다.
  • 공통 컬러 및 타이포그래피: 주조색(#333)과 포인트 블루(#4a90e2), Pretendard 폰트 변수를 공통으로 사용했습니다.
  • 모바일 환경 대응: 768px 이하 해상도를 기준으로 카드 배치를 1열로 전환하고 텍스트와 이미지가 잘리지 않도록 설계했습니다.

Git · GitHub 협업 워크플로우

  • 이슈 기반 작업 관리: 코드를 작성하기 전에 담당 페이지의 구현 항목을 Issue로 먼저 정의하고 번호를 부여했습니다.
  • 브랜치 분리 및 직접 Push 제한: main 브랜치 직접 수정을 금지하고, 모든 작업은 feature/* 브랜치에서 독립적으로 진행했습니다.
  • PR 템플릿 및 상호 승인: PC·모바일 테스트 체크리스트를 통과한 뒤 PR을 올리고, 다른 팀원의 확인을 거쳐 병합합니다.
